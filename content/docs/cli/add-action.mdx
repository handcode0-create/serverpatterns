# serverpatterns add action

Génère une Server Action Next.js hautement sécurisée, validée par Zod et protégée par un contrôle d'accès basé sur les rôles (RBAC) en une seule commande.

## Syntaxe de la commande

Passez le nom de l'action souhaitée en argument ou lancez simplement la commande pour utiliser l'assistant interactif :

```bash
npx serverpatterns add action <nom-action>
```

---

## Assistant interactif de génération

Le CLI intègre un générateur de schéma Zod dynamique pour structurer rapidement vos payloads d'entrée :

1. **Nom de l'Action** : ex. `update-inventory` (si non fourni en argument)
2. **Boucle interactive de construction du schéma Zod** :
   - Demande le nom du champ (laisser vide pour terminer)
   - Pour chaque champ, demande son type : `string` | `number` | `boolean`
   - Demande s'il est optionnel (Oui/Non)
   - *Exemple de boucle* : création d'un schéma pour `sku` (string, requis) et `quantity` (number, requis)
3. **Restriction RBAC (Contrôle d'accès basé sur les rôles)** :
   - *"Cette action doit-elle être restreinte à certains rôles (RBAC) ?"* (Oui/Non)
   - Si oui, saisie des rôles autorisés séparés par une virgule, ex: `admin, stock_manager`

## Fichier unique généré

Le CLI crée une Server Action unifiée sous `app/actions/update-inventory.ts` :

```typescript
"use server";

import { z } from "zod";
import { withAuth, ok, err } from "@serverpatterns/next";
import { ServerPatternsError } from "@serverpatterns/core";
import { getSession } from "@/lib/auth/session"; // TODO: À implémenter

// Schéma d'entrée généré automatiquement par la boucle interactive
const inputSchema = z.object({
  sku: z.string(),
  quantity: z.number(),
});

export const updateInventory = withAuth({
  getSession,
  requiredRoles: ["admin", "stock_manager"],
  inputSchema,
  action: async (input, session) => {
    try {
      // TODO: Écrivez votre logique métier ici
      // input.sku et input.quantity sont typés et garantis valides !
      // session.userId et session.roles sont sécurisés et disponibles !
      
      return ok({
        success: true,
        sku: input.sku,
        updatedQuantity: input.quantity,
      });
    } catch (cause) {
      return err(
        new ServerPatternsError(
          "SERVER_ERROR", 
          "Échec de la mise à jour de l'inventaire", 
          { cause }
        )
      );
    }
  },
});
```

## Note d'ingénierie : L'adaptateur de session

L'adaptateur de session `getSession` n'est pas fourni clé en main par ServerPatterns car il dépend de votre fournisseur d'auth (NextAuth, Clerk, Kinde, JWT sur mesure). C'est à vous d'exposer une fonction respectant cette signature :

```typescript
// lib/auth/session.ts
import { cookies } from "next/headers";

export async function getSession() {
  const token = (await cookies()).get("session_token")?.value;
  if (!token) return null;
  
  // Exemple de décodage d'un token JWT
  try {
    const payload = decodeJwt(token);
    return {
      userId: payload.sub,
      roles: payload.roles || [], // Tableau de rôles ex. ["admin", "stock_manager"]
    };
  } catch {
    return null;
  }
}
```

## Conseil IA d'ingénierie

> 💡 **CONSEIL AGENT IA :**
> Le wrapper `withAuth` injecte automatiquement la session validée en second paramètre du handler. Ne refaites pas d'appel à `getSession()` ou de vérification manuelle de rôles à l'intérieur du corps de l'action. L'exécution n'atteint le code métier que si l'utilisateur est authentifié et possède les rôles requis, réduisant considérablement la surface d'erreur.
