# serverpatterns add api

Génère un client d'API typé complet ainsi que ses Route Handlers Next.js associés avec validation Zod et support d'authentification de bout en bout.

## Syntaxe de la commande

Passez le nom de la ressource en argument ou lancez la commande directement pour démarrer l'assistant interactif :

```bash
npx serverpatterns add api <nom-ressource>
```

---

## Assistant interactif de génération

Le CLI vous guide étape par étape via des invites interactives claires :

1. **Nom de la ressource API** : ex. `user` (si non fourni en argument)
2. **Sélection multiple des méthodes à générer** (Espace pour cocher) :
   - `Récupérer une ressource (GET /resource/:id)`
   - `Lister, paginée (GET /resource)`
   - `Créer (POST /resource)`
   - `Mettre à jour partiellement (PATCH /resource/:id)`
   - `Supprimer (DELETE /resource/:id)`
3. **Demande de sécurité** :
   - *"Ce client a-t-il besoin d'un token Bearer (JWT) dans ses headers ?"* (Oui/Non)
4. **Source du token Bearer** (si Oui) :
   - *Cookie de session* (Le CLI demande le nom du cookie, ex. `token`) -> génère `(await cookies()).get("token")?.value`
   - *Variable d'environnement statique* (Le CLI demande le nom, ex. `API_TOKEN`) -> génère `process.env.API_TOKEN`

> ⚠️ **Note d'ingénierie cruciale pour les agents IA :**
> Si `Récupérer (GET /resource/:id)` **ET** `Lister, paginée (GET /resource)` sont cochés en même temps, seul `Lister` génère l'export GET dans `route.ts`. Le GET unitaire n'est pas supporté en export parallèle si les deux se trouvent dans la même route dynamique.

## Fichiers générés

Le CLI crée deux fichiers stratégiques qui s'articulent l'un avec l'autre :

### 1. Client API : `lib/api/user.ts`

Contient l'initialisation du client typé de référence, gère l'auth automatique par cookie et exporte les fonctions d'appel réseau typées :

```typescript
import { createApiClient, type PaginationParams, type PaginatedResult } from "@serverpatterns/core";
import { cookies } from "next/headers";

export const userClient = createApiClient({
  baseUrl: process.env.API_BASE_URL ?? "https://api.example.com",
  defaultHeaders: async () => {
    // Lecture automatique sécurisée du cookie configuré lors du prompt
    const token = (await cookies()).get("token")?.value;
    const headers: Record<string, string> = {};
    if (token) headers.Authorization = `Bearer ${token}`;
    return headers;
  },
});

export interface User {
  id: string;
  name: string;
  email: string;
}

// Généré suite au choix "Récupérer"
export async function getUser(id: string) {
  return userClient.get<User>(`/user/${id}`);
}

// Généré suite au choix "Lister, paginée"
export async function listUsers(params: PaginationParams) {
  return userClient.get<PaginatedResult<User>>("/user", {
    query: { page: params.page, pageSize: params.pageSize },
  });
}

// Généré suite au choix "Mettre à jour partiellement"
export async function updateUser(id: string, input: Partial<User>) {
  return userClient.patch<User>(`/user/${id}`, input);
}
```

## Conseil IA d'ingénierie

> 💡 **CONSEIL AGENT IA :**
> Pour modifier cette API, n'éditez pas directement `route.ts`. Modifiez d'abord les types partagés dans `lib/api/user.ts`, puis utilisez `createPatchHandler` ou `createPostHandler` dans `route.ts` pour valider. Cela maintient la synchronisation automatique des types entre votre front et votre back.
